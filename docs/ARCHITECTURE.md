# Architecture

The ALIEV.IO website (digital studio): main page, Careers, Contact, Downloads, Auth and the retained `_api` bundle.
PHP 8.3, no framework, Apache in Docker, MariaDB for accounts and job postings. The folder names are the canonical ALIEV.IO
structure; only folders with real content exist (no `apps/*`, `api/v2`, `core/users`, `core/permissions`, `core/cache`,
`website/legal`, `website/investors` — they appear when they have something to hold).

Where does X go?

| I want to… | …put it in |
|---|---|
| add a page | `website/<page>/` (controller, `views/`, `assets/`), route in `routes/web.php`, wiring in `core/Application.php` |
| use header, navbar, form protection fields | the components in `resources/views/components/` — never copy their markup |
| style something shared | `resources/css/components/*.css`; page-only styles stay in `website/<page>/assets/css` |
| read/write the database | a model in the page folder (`website/careers/JobRepository`) or `core/auth` — prepared statements only |
| call a third party / send a message | `core/services/` (timeouts; must not throw into the request) |
| protect a form | `FormGuard` in the controller + `components/guard-fields` in the view |
| add a setting | env var → `.env.example` → `config/*.php` |
| add an endpoint for the site's pages | `api/internal` (JSON) — the `_api` allow-list in `api/terminal` is a compatibility surface |

## 2. Rules

1. Minimal MVC: `route → controller → (model | service) → view`. No abstraction without a second consumer.
2. Explicit wiring in `Core\Application`; no container, no globals.
3. One of each security primitive: one session manager and one CSRF implementation (`core/auth`), built once in `Application`.
4. Templates are dumb: every value through `$e()`; no inline `<script>`, `<style>`, `style=""`, `on*=` (CSP).
5. One implementation per shared UI element (§5). Page-specific variants stay in the page folder.
6. Design is not architecture: ported CSS/JS keep the look and behaviour of the original.

## 3. Request lifecycle

Apache serves real files under `public/` (including the generated `build/` and `home/_api/`), answers 404 for dotfiles and any `.php` except `index.php`, serves a directory that ships an `index.html` at its slash URL, and sends everything else to `public/index.php` → `Application::handle()`: canonical path (trailing slash stripped except under `/home/_api/`) → optional HTTPS redirect → `Router::dispatch()` → `HttpException` becomes an error page, any other `Throwable` is logged and shown as a generic 500 → `SecurityHeaders` on every response.

## 4. Views and assets

- **Views**: `View` has named roots — `shared` = `resources/views`, plus `home`, `careers`, `contact`, `downloads` = `website/<page>/views`, `auth` = `core/auth/web/views`. `render('careers::show', …, 'page')`, `partial('components/navbar', …)`. Names are validated (no `..`, no absolute paths).
- **Assets**: sources live in `resources/{css,js,images,icons,fonts,vendor}`, `website/<page>/assets` and `core/auth/web/assets`. `scripts/build.php` publishes an allow-list of web file types to `public/build/<same name | page>/` (incrementally, mtimes preserved so `View::asset()`'s `?v=` only changes when a file does) and the `_api` bundle to `public/home/_api/`. It runs in the container entrypoint, the prod image build and the phpunit bootstrap; run it yourself after editing a source in a bind-mounted checkout. Non-web fonts (SF Pro, DotlineBold) are never published. Downloadable files stay in `public/downloads/`.

## 5. Shared components

| Component | Where | Used by |
|---|---|---|
| Document head | `components/head.php` | every layout |
| Navbar (rail, hamburger or icon link, logo, optional menu / quick-link slots) | `components/navbar.php` + `css/components/navbar.css` | main page (`leading=menu`), Careers, Contact, Downloads, Auth, error pages (`leading=link`) |
| Form protection fields (CSRF, form age, honeypot) | `components/guard-fields.php` + `css/components/forms.css` | hire, contact, sign-up, login, logout |
| ALIEV button / ripple | `css/components/button.css` + `js/ripple.js` | every page |
| Fonts | `css/fonts/<family>.css` | one declaration per family (Poppins, Montserrat, Open Sans, Doto/Ndot, …) |

Not invented: the design has no footer and no breadcrumbs; cards, inputs and buttons of the original pages differ per page (Careers list, Downloads cards, Auth fields, profile panel) and stay page-scoped. The navbar's two variants are the original's: the main page has the hamburger and menu panels, the other pages the same rail with a home/back icon (the Settings/Widgets menu is not pushed onto them). Two deliberate consolidations: Contact's icon is 17 px like the others (it was 16), and Auth's logo sits at y=60 like every page (it was 56, caused by Bootstrap's 16 px root).

## 6. Pages

| Page | URL | Controller · views |
|---|---|---|
| Main | `/` | `Website\Home\HomeController` · `home::home` on `layouts/shell` |
| Hire form | `POST /hire` | `HireController` |
| Careers | `/careers`, `/careers/{slug}`, `/careers/team` | `Website\Careers\CareersController`, `JobRepository` |
| Contact | `/contact` | `Website\Contact\ContactController` |
| Downloads | `/downloads` | `Website\Downloads\DownloadsController` (`config/downloads.php`) |
| Auth | `/home/auth`, `…/reset`, POST `…/{login,register,logout}` | `Core\Auth\Web\AuthController` |
| Widgets | `/widgets/{clock,calculator}` | `Website\Home\WidgetController` |
| Prices | `/api/prices` | `Api\Internal\PricesController` |
| `_api` | `/home/_api/` + allow-listed endpoints | `Api\Terminal\ApiController` + static bundle |

**URLs and `_api`.** Application routes have no trailing slash; `/home/_api/` keeps it (the static bundle uses relative paths). `GET /home/_api/` → 302 `/home/_api/UI/`. Endpoints are an explicit allow-list (`hello`, `info`, `me`, `updates`, `csrf`, `tools/domain`, `valentine/yes`): no dispatch from the URL, no CORS, `no-store`, CSRF + rate limits on state change. The strict site CSP applies everywhere except the static bundle (`docker/apache/api-csp.conf`, a documented allow-list). Historical URLs: `routes/legacy.php`, `URL-MIGRATION.md`.

## 7. Security, data, Docker
- **Security** — see `SECURITY.md`: one session/CSRF; `FormGuard` pipeline on public forms; prepared statements only; secrets only from the environment; strict CSP with documented exceptions; generic errors.
- **Data** — accounts and jobs in MariaDB (`database/migrations`); leads, rate limits, price cache and logs as files in `storage/`. `database/seeds/dev-jobs.sql` is fictional sample data loaded only when `SEED_DEV_DATA=true`.
- **Docker** — `Dockerfile` (stages `vendor` → `base` → `dev` | `prod`, `php:8.3-apache`; Apache's master runs as root to bind the port, workers as `www-data`). `compose.yaml`: `app` + `db`. The entrypoint runs `composer install` (dev), `scripts/build.php`, migrations (and seeds in development).

## 8. Testing
PHPUnit (`tests/Unit`, `tests/Feature`; the bootstrap publishes assets), PHPStan level 8 over `core`, `website`, `api`, `config`, `routes`, php-cs-fixer, and the browser tools in `scripts/visual`. `baseline.mjs` + `compare-baseline.py` prove a restructuring changed nothing: rendered HTML, requested URLs, console errors and chrome boxes of every route at four viewports. See `TESTING.md`.
